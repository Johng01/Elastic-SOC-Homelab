# SOC-WIN-002 — Remote Failed Authentication Investigation Report

## 1. Executive Summary

On October 17, 2026, Elastic Security generated an alert after detecting five failed Windows network authentication attempts originating from Kali Linux.

The authentication attempts targeted a Windows Enterprise Evaluation virtual machine through Remote Desktop Protocol (RDP) with Network Level Authentication (NLA).

The detection was generated by the custom Elastic Security threshold rule:

**SOC-WIN-002 — Multiple Remote Failed Logon Attempts**

The rule grouped Windows Security Event ID 4625 records by their originating IP address and generated an alert after the configured threshold of five failures was reached.

Investigation established that the activity originated from an authorized Kali Linux test machine and was intentionally generated to validate the SOC detection rule.

No matching successful network authentication events from the test source were found during the investigated period.

**Final disposition: Benign Positive — Authorized Security Testing.**

The detection itself was a true positive because the observed authentication failures genuinely occurred.

## 4. Investigation Scope

The investigation focused on:

1. Confirming that remote authentication failures occurred.
2. Identifying the originating IP address.
3. Verifying Windows Security Event ID 4625.

The investigation was limited to the authorized SOC homelab environment.

## 5. Detection Logic

### 5.1 Detection Query

The following KQL query was configured in Elastic Security:

```kql
host.name : "windows-client" and
event.code : "4625" and
winlog.channel : "Security" and
winlog.event_data.LogonType : "3" and
source.ip : * and
not source.ip : ("127.0.0.1" or "::1")
```

### 5.2 Threshold Configuration

| Setting | Value |
|---|---|
| Grouping Field | source.ip |
| Threshold | 5 |
| Execution Interval | 5 minutes |
| Additional Look-back | 1 minute |
| Approximate Search Window | 6 minutes |
| Severity | Medium |
| Risk Score | 47 |

The rule identified repeated failed network authentication events associated with the same originating IP address.

Logon Type 3 is not exclusive to RDP. In this investigation, the authentication method was established through the controlled FreeRDP/NLA test.

### 7.3 Certificate Verification

The FreeRDP test used `/cert:ignore` to bypass certificate validation in the controlled laboratory environment.

This setting should not be used as a standard production configuration because it prevents reliable detection of server impersonation through certificate validation.

## 11. Successful Authentication Investigation

### Investigation Question

Did the failed authentication attempts lead to a successful Windows network logon from the same source IP?

### Investigation Method

Windows Security Event ID 4624 was examined using PowerShell.

The search was restricted to:

- Event ID: 4624
- Logon Type: 3
- Source IP: 192.168.100.245
- Start: 2026-10-17 17:30:00
- End: 2026-10-17 18:00:00

### Investigation Command

```powershell
Get-WinEvent -FilterHashtable @{
    LogName='Security'
    Id=4624
    StartTime=[datetime]'2026-10-17 17:30:00'
    EndTime=[datetime]'2026-10-17 18:00:00'
} -ErrorAction SilentlyContinue |
Where-Object {
    $_.Properties[8].Value -eq 3 -and
    $_.Properties[18].Value -eq '192.168.100.245'
} |
Select-Object TimeCreated, Id,
    @{Name='TargetUser';Expression={$_.Properties[5].Value}},
    @{Name='LogonType';Expression={$_.Properties[8].Value}},
    @{Name='SourceIP';Expression={$_.Properties[18].Value}} |
Format-Table -AutoSize
```

### Result

The command returned no matching events.

### Analyst Interpretation

No successful network authentication from Kali Linux was observed within the specified investigation window.

This result does not establish that successful authentication could never occur or that all possible authentication mechanisms were examined.

It supports the conclusion that no successful network logon matching the investigated criteria was recorded during the test period.

## 12. Findings

### Finding 1 — Remote Authentication Failures Confirmed

Five controlled RDP/NLA authentication attempts were made from Kali Linux.

All five were rejected.

### Finding 2 — Source Attribution Confirmed

Windows and Elastic Security identified the originating address as:

`192.168.100.245`

### Finding 3 — Detection Rule Functioned Correctly

The threshold rule generated an alert with a matching event count of five.

### Finding 4 — No Matching Successful Network Logons

No Event ID 4624 records meeting the specified investigation criteria were found.

### Finding 5 — Activity Was Authorized

The authentication attempts were intentionally generated as part of SOC-WIN-002 detection validation.

There was no evidence that the test represented unauthorized access.

## 13. Incident Classification

### Detection Assessment

**True Positive**

The detection accurately identified the behavior it was designed to detect: repeated failed Windows network authentication attempts originating from one IP address.

### Activity Assessment

**Benign Positive**

The underlying authentication failures were generated intentionally during authorized security testing.

### Final Disposition

**Benign Positive — Authorized Security Testing**

The alert was closed after the investigation findings were documented in Elastic Security.

## 14. Impact Assessment

The test involved a deliberately nonexistent account.

No successful remote authentication was observed.

No evidence of account compromise or unauthorized system access was identified within the investigation scope.

The exercise was limited to the authorized laboratory environment.
