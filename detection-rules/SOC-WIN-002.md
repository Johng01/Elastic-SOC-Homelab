## 2. Detection Objective

Detect repeated failed Windows network authentication attempts
originating from the same source IP address.

The detection identifies potentially suspicious authentication
activity consistent with brute-force attempts, password spraying,
or other unauthorized remote authentication attempts.

The rule is not limited exclusively to Remote Desktop Protocol
(RDP). It monitors Windows Security Event ID 4625 with Logon
Type 3, which may be generated by different network
authentication mechanisms.

## 4. Detection Data Source

Index pattern:

`logs-system.security-default`

Required event fields:

| Field | Purpose |
|---|---|
| host.name | Identifies the monitored Windows endpoint |
| event.code | Identifies failed authentication Event ID 4625 |
| winlog.channel | Restricts events to the Windows Security log |
| winlog.event_data.LogonType | Identifies network logon attempts |
| source.ip | Identifies the originating IP address |
| winlog.event_data.TargetUserName | Identifies the targeted username |

## 5. Detection Query

Query language: KQL

```kql
host.name : "windows-client" and
event.code : "4625" and
winlog.channel : "Security" and
winlog.event_data.LogonType : "3" and
source.ip : * and
not source.ip : ("127.0.0.1" or "::1")
```

## 6. Threshold Configuration

| Setting | Value |
|---|---|
| Rule Type | Threshold |
| Group By | `source.ip` |
| Threshold | 5 matching events |
| Runs Every | 5 minutes |
| Additional Look-back | 1 minute |
| Effective Search Window | Approximately 6 minutes |
| Alert Suppression | Disabled |

The rule groups failed network authentication events by source IP.

An alert is generated when five or more matching events from the
same source IP are detected within the evaluation window.

## 8. Controlled Authentication Test

### Objective

Validate that five failed remote authentication attempts from
the same source IP generate a threshold alert in Elastic Security.

### Test Environment

| Component | Value |
|---|---|
| Source system | Kali Linux |
| Source IP | 192.168.100.245 |
| Destination system | windows-client |
| Destination IP | 192.168.100.183 |
| Destination port | TCP 3389 |
| Authentication protocol | RDP with NLA |
| Test username | SOC-Test-Remote-Invalid |
| Authentication attempts | 5 |

The test used a deliberately nonexistent account and a disposable
incorrect password.

Testing was performed exclusively within the authorized SOC homelab.

### Authentication Test Command

Executed from Kali Linux:

```bash
for i in {1..5}; do
    printf '\n=== SOC-WIN-002 Test Attempt %s/5 ===\n' "$i"
    printf 'SOC-Lab-Invalid-Password\n' | xfreerdp3 \
        /v:192.168.100.183 \
        /u:SOC-Test-Remote-Invalid \
        /d:windows-client \
        /cert:ignore \
        /sec:nla \
        +auth-only \
        /from-stdin:force
    sleep 5
done
```

The `/cert:ignore` option bypasses RDP certificate verification.
It was used only for this controlled laboratory experiment and
should not be considered a secure production configuration.

### Test Results

The five authentication attempts occurred on October 17, 2026,
between approximately 17:36:59 and 17:37:21.

Each attempt resulted in:

`ERRCONNECT_LOGON_FAILURE [0x00020014]`

All five attempts were rejected during authentication.

## 13. False Positive Considerations

Potential benign causes of repeated authentication
failures include:

- Users repeatedly entering incorrect passwords.
- Services using outdated credentials.
- Misconfigured applications.
- Automated authentication retries.
- Authorized penetration testing.
- SOC detection-validation exercises.

A detection alert requires investigation and should
not automatically be classified as malicious.

## 14. Detection Limitations

### Source IP Grouping

The rule groups events by `source.ip`.

Multiple users behind a shared NAT address may be
grouped together.

Distributed attacks involving several source IP
addresses may not reach the threshold.

### Network Authentication Scope

Windows Logon Type 3 is not exclusive to RDP.

The detection covers failed network authentication
events, including RDP/NLA authentication failures.

### Detection Window

The current rule runs every five minutes with an
additional one-minute look-back.

Slow authentication attempts spread across longer
periods may evade this threshold.

### Late-Arriving Events

Events arriving outside the effective detection
window may not be included in the intended evaluation.

### Laboratory Host Restriction

The query currently monitors only:

`host.name : "windows-client"`

Production deployment would require an appropriate
scope covering additional Windows endpoints.

## 15. Recommended Improvements

Future detection improvements include:
